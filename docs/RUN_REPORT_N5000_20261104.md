# The n=5000 production run, end to end (2026-11-04 to 2026-11-16)

This report covers how the n=5000 run was produced, from the ClinicalTrials.gov export to the final decision model:
trial selection, synthetic protocols, cohort extraction, synthetic patients, summaries, teacher labels, TrialSpace, and
the decision model. It was written on 2026-11-16 from the run's own records.

- **Data:** synthetic patients and public ClinicalTrials.gov text only. No PHI went into this run.
- **Status:** the artifacts are local and unpublished. This is not a v23 release.
- **Purpose:** MatchMiner-AI is a human-in-the-loop prioritization tool, not an eligibility engine. Every metric below
  is a synthetic, mostly in-sample diagnostic.

**Path abbreviations** (relative to `/ksg/kehl_mm_data/mmai/v23/`):
- **U:** `data/no_phi/training_run_screened_sample5000_20261104/`. The run folder up to the notes; also copied, with
  identical files, to `L/as_generated/`.
- **L:** `data/no_phi/synthetic_dataset_n5000_screened_20261106/`. The dataset folder: the v4 trial artifacts, the
  summaries, and every TrialSpace and decision-model stage.
- **T:** `L/trialspace/`.

**Source labels in the tables:**
- **README-U**, **README-L:** `U/README.txt` and `L/README.txt`, the dated logs kept during the run.
- **"memory":** the session's working notes. Used only where no run file records the fact, and marked.

Times are UTC where the source is a receipt and EST where the source is a README.

## 4. Cohort extraction, both versions

Each trial is represented twice: by cohorts from its synthetic protocol, and by cohorts from its ctgov listing. Both
versions go through the inference package's stepwise workflow with the same prompts:
- a cancer-treatment screen;
- the cohort names;
- one request per cohort for its complete criteria, copied verbatim (schema `trial-cohorts-stepwise-v1`, rows
  `trial-treatment-cohorts-v5`).

Training then merges each trial's equivalent cohorts and classifies every criteria line as key or boilerplate, one
request per line.

### 7.5 Question-7 criteria relabel (2026-11-13/14)
- **Problem:** on the dashboard, patients "failed" criteria that don't apply to them, such as an alternative they don't
  take.
- **Cause:** the original prompt said to judge each line on its own (memory: `criteria-structure-prompt`).
- **Fix:** inference 6aa919d, "Judge each criteria line in its role: alternatives, conditionals and branches", patched
  into the frozen inference copy. It changed the criteria contract from 2728713a to 7a7eb230 and the decision questions
  digest from fe101311 to c0a48804 (`L/source/trialspace_20261106/before_criteria_structure_20261113/README.md`).
  A v5 revision was tested and not adopted.
- **Scope:** all 2,931,822 lines were relabeled (user: "we'll relabel all lines"). The original labels stay in
  `criteria_teacher_v0_20261110/`.
- **Servers:** the GB300 and the B200 Spot VMs found by two hunts on 2026-11-13: mmai-b200-3, then mmai-b200-6
  (`T/b200_relabel_20261113.json`, `T/b200_relabel2_20261113.json`, `T/label_concurrency_relabel_20261113.json`).

### 8.2 Training
- **Method:** full fine-tune with transformers' Trainer. The loss is the yes/no cross-entropy at each answer slot only,
  over the best yes form against the best no form (the readout loss). d1-2B uses `set` attention, so answers are never
  appended.
- **Settings** (identity `decision-model-v2`, `T/models/decision_model/stage_receipt.json`):
  - 8 GPUs × 8 states, gradient accumulation 4, so 256 states per step;
  - lr 1e-5 with 3% warmup, 1 epoch;
  - 16,930,707 / 256 = 66,136 steps;
  - checkpoints every 1,000 steps.

## 13. Caveats
- **In-sample metrics:** these are in-sample diagnostics on synthetic data. The policy is all synthetic data and no
  holdouts, and the smoke-test "held-out" pairs share their cohorts with training. None of these numbers estimate
  performance on real patients, a new site, or current protocols.
- **Labels:** labels are one teacher model's judgments, not clinician review. Synthetic notes come from the same model
  family, so systematic teacher errors can pass into both the data and the labels.
- **Decision model:** it ranks and screens; it does not decide eligibility. High-ranked pairs still need review by a
  clinician and the trial team against the complete, current protocol.
- **Ad hoc steps:** several stages were finished or handed over by hand: supervisor versions, in-place patches of the
  frozen code, and the hand-finished decision release. Each step is recorded in README-L or in the `before_*` folders
  beside the patched code.
